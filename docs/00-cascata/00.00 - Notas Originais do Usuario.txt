# Engenharia de Descoberta Biomolecular

Não:

```text
BIOLOGIA
   ↓
"descobrir como a célula funciona"
```

Mas:

```text
OBSERVAÇÕES
     ↓
ORGANIZAÇÃO
     ↓
CRUZAMENTO DE EVIDÊNCIAS
     ↓
DETECÇÃO DE INCERTEZAS
     ↓
HIPÓTESES TESTÁVEIS
     ↓
EXPERIMENTAÇÃO
     ↓
NOVAS EVIDÊNCIAS
     ↺
```

O objetivo é **reduzir incerteza**.

## E aqui RF/RNF fica muito poderoso

Em vez de:

> RF: a kinesina deve transportar carga.

Podemos definir:

### RF-001 — Representação

O sistema deve representar uma entidade molecular sem perder:

* identidade;
* localização;
* estado conformacional;
* interações;
* temporalidade;
* concentração;
* contexto celular;
* evidência associada.

### RF-002 — Cruzamento

O sistema deve correlacionar observações independentes sobre a mesma entidade.

Por exemplo:

```text
proteína X
│
├── estrutura
├── expressão
├── localização
├── interações
├── modificações
├── mutações
├── fenótipos
├── literatura
├── ensaios
└── resultados negativos
```

### RF-003 — Contradição

O sistema deve **procurar ativamente evidências incompatíveis**.

Isso é enorme.

Não queremos um sistema que encontre dez artigos dizendo:

> X está relacionado a Y.

Queremos:

```text
X → Y

e procurar:

X ↛ Y
X → Z
Y → X
contexto A: sim
contexto B: não
```

### RF-004 — Proveniência

Toda afirmação deve possuir uma cadeia:

```text
CLAIM
 ↓
EVIDENCE
 ↓
EXPERIMENT
 ↓
CONDIÇÕES
 ↓
MÉTODO
 ↓
DADOS
```

Sem isso, uma hipótese antiga pode virar "fato" simplesmente porque foi repetida mil vezes.

# E o RNF mais importante

### RNF-001 — Epistemic Integrity

O sistema **não pode transformar inferência em fato**.

Eu faria até uma enumeração:

```text
UNKNOWN
OBSERVED
REPORTED
INFERRED
HYPOTHESIZED
MODELED
VALIDATED
CONTRADICTED
```

E uma coisa deliciosa:

```text
confidence ≠ evidence
```

Uma coisa pode ter:

```text
100 papers
```

e continuar sendo uma inferência derivada do mesmo experimento original.

Enquanto outra pode ter:

```text
3 experimentos independentes
```

e possuir evidência experimental muito mais interessante.

# E podemos fazer uma coisa ainda melhor

**Reprodução computacional.**

Antes de tentar descobrir alguma coisa nova:

1. escolhemos um fenômeno;
2. encontramos dados experimentais;
3. implementamos o modelo publicado;
4. reproduzimos os resultados;
5. verificamos onde nosso modelo diverge;
6. investigamos a divergência.

Isso é praticamente **engenharia reversa de conhecimento científico**.

       ↓

       ↓

Não estamos dizendo que esse é **o mecanismo verdadeiro completo**.

Estamos construindo um modelo computacional baseado em observações e perguntando:

> **Esse conjunto mínimo de estados consegue reproduzir os dados conhecidos?**

Se não consegue, temos um problema interessante.

# A principal melhoria: mudar o centro do sistema

Eu corrigiria uma coisa da proposta anterior.

Não faria:

```text
                  CELL LAB
                     │
              ┌──────┴──────┐
              │             │
          Simulação       Dados
```

Faria:

```text
                     EVIDÊNCIA
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
       DADOS          MODELOS       LITERATURA
          │              │              │
          └──────────────┼──────────────┘
                         ▼
                   CONHECIMENTO
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
       SUPORTE       CONTRADIÇÃO     LACUNA
          │              │              │
          └──────────────┼──────────────┘
                         ▼
                    HIPÓTESE
                         │
                         ▼
                    PREDIÇÃO
                         │
                         ▼
                     TESTE
```

**A simulação deixa de ser protagonista.**

Ela vira uma ferramenta entre várias.

Isso é uma melhoria arquitetural importante.

---

# 1. Criaria um "Knowledge Graph" científico

Esse seria provavelmente o coração do projeto.

```text
                    KIF5B
                      │
         ┌────────────┼─────────────┐
         ▼            ▼             ▼
     estrutura      ATP          microtúbulo
         │            │             │
         ▼            ▼             ▼
     Evidence A    Evidence B    Evidence C
         │            │             │
         └────────────┼─────────────┘
                      ▼
                   MODEL-17
                      │
                      ▼
                 PREDICTION-4
```

Mas cada aresta teria:

```yaml
source:
evidence_type:
condition:
organism:
cell_type:
measurement:
date:
method:
provenance:
status:
```

Isso permitiria responder:

> "Por que o sistema acredita que X está relacionado a Y?"

Sem depender de uma IA dizendo "porque a literatura afirma".

---

# 2. Criaria um "Evidence Ledger"

Essa seria uma das partes mais importantes.

Cada afirmação teria um registro:

```yaml
claim_id: CLM-000184

claim:
  "KIF5B transporta determinado cargo."

status: INFERRED

evidence:
  - EXP-0012
  - EXP-0091
  - EXP-0134

conditions:
  temperature: 37C
  system: in_vitro

limitations:
  - "não representa plenamente o citoplasma"

contradictions:
  - null
```

E poderíamos clicar:

**Claim → Evidências → Experimentos → Dados brutos**

Isso evita o problema clássico:

```text
paper A
 ↓
paper B cita A
 ↓
paper C cita B
 ↓
paper D cita C
 ↓
"é conhecido que..."
```

Quando, na realidade, tudo pode remontar ao **mesmo experimento**.

---

# 3. Criaria uma matriz de desconhecimento

Isso seria excelente para o Método Caracol.

```text
                    CONHECIMENTO
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
      FORTE           FRÁGIL          AUSENTE

      ████████         ████░░░░        ░░░░░░░░
```

Mas não usaríamos uma "nota de certeza" arbitrária.

Seria baseado em propriedades mensuráveis:

```text
número de experimentos independentes
qualidade metodológica
reprodutibilidade
consistência
distância entre sistemas experimentais
quantidade de evidência contraditória
```

---

# 4. Introduziria "Experimentos Virtuais"

Aqui começa a ficar muito interessante.

Você poderia alterar:

```text
ATP       100% → 40%
Crowding   baixo → alto
Cargo      A → B
Temperatura 37 → 25 °C
```

E clicar:

> **Executar**

O sistema produziria:

```text
OBSERVADO:
não temos experimento correspondente.

MODELO:
prevê redução de velocidade.

CONFIANÇA DO MODELO:
não calculada como "certeza".

EVIDÊNCIA:
fraca/moderada.

STATUS:
PREDIÇÃO NÃO VALIDADA.
```

Isso é muito melhor do que:

> "Resultado: 43% menos velocidade."

Porque o segundo pode parecer um fato experimental.

---

# 5. Criaria "Model Competition"

Em vez de:

```text
NOSSO MODELO
```

teríamos:

```text
          FENÔMENO X
               │
       ┌───────┼───────┐
       ▼       ▼       ▼
      M1      M2      M3
```

Cada modelo faz previsões.

```text
M1 → P1
M2 → P2
M3 → P3
```

E então perguntamos:

> **Qual observação diferenciaria esses modelos?**

Essa é uma melhoria enorme.

Porque o objetivo deixa de ser provar nosso modelo.

Passa a ser **descobrir qual experimento possui maior poder discriminatório**.

---

# 6. Eu acrescentaria um "Experiment Designer"

Esse seria talvez o módulo mais ambicioso.

Imagine:

```text
HIPÓTESES ATUAIS

H1 ──────────────── 0.72
H2 ────────────     0.51
H3 ─────────────    0.48
```

E:

```text
EXPERIMENTOS POSSÍVEIS

E1 → separa H1/H2        █████████
E2 → separa H2/H3        ██████
E3 → pouca informação    ██
```

O sistema não diz:

> "Faça E1 porque é o melhor."

Ele mostra:

> **"E1 possui maior poder potencial para distinguir os modelos sob estas premissas."**

Isso é muito mais cientificamente interessante.

---

# 7. E precisamos de uma coisa extremamente importante

## Negative Knowledge

Registrar:

> **o que não funcionou.**

Não apenas:

```text
X → Y [VALID]
```

Mas:

```text
X → Y
│
├── condição A [VALID]
├── condição B [VALID]
├── condição C [FAIL]
└── condição D UNKNOWN
```

Resultados negativos são extremamente valiosos para evitar que o sistema percorra novamente caminhos mortos.

---

# 8. Segurança científica

Eu colocaria um mecanismo chamado:

## Epistemic Firewall

Antes de qualquer saída:

```text
RESULTADO
   │
   ▼
┌─────────────────────┐
│ É dado experimental?│
└──────────┬──────────┘
           │
       NÃO ▼
┌─────────────────────┐
│ É resultado de      │
│ simulação?          │
└──────────┬──────────┘
           │
       NÃO ▼
      HIPÓTESE
```

A UI usaria símbolos extremamente claros:

```text
[EXPERIMENTAL] EXPERIMENTAL
[MODELADO] MODELADO
[INFERIDO] INFERIDO
[?] UNKNOWN
[ALERT] CONTRADITÓRIO
[PREDICAO] PREDIÇÃO
```

Isso evitaria uma das maiores armadilhas de sistemas científicos com IA:

**gerar uma narrativa plausível e apresentá-la como conhecimento.**

## RNFs

### RNF-001 — Reprodutibilidade

Mesma entrada + mesma versão do modelo → mesmo resultado, quando o método for determinístico.

### RNF-002 — Proveniência

Nenhum dado científico pode existir sem origem conhecida.

### RNF-003 — Auditabilidade

Toda conclusão deve ser rastreável.

### RNF-004 — Epistemic Integrity

O sistema não pode representar hipótese como observação.

### RNF-005 — Versionamento

Alterações nos dados/modelos devem ser rastreáveis.

### RNF-006 — Interoperabilidade

Preferir formatos científicos existentes em vez de inventar tudo.

### RNF-007 — Escalabilidade

O sistema deve permitir crescer de uma proteína para redes moleculares sem reescrever o núcleo.

### RNF-008 — Observabilidade

Toda execução de modelo deve gerar logs suficientes para reprodução.

### RNF-009 — Incerteza

Parâmetros desconhecidos não devem ser silenciosamente preenchidos.

### RNF-010 — Falsificabilidade

Modelos devem ser capazes de produzir previsões potencialmente contraditórias por observação.

# Minha avaliação final

A primeira versão era uma ideia boa de **"laboratório virtual"**.

Depois dessas melhorias, eu a classificaria como algo mais interessante:

> **uma plataforma de engenharia de conhecimento científico para integrar evidência biomolecular, modelos computacionais e hipóteses testáveis.**

**Conceito: 9,5/10.**

O próximo passo, porém, **não é programar**.

É escolher o **primeiro fenômeno** e fazer o Ciclo 0:

```text
                 CICLO 0
                    │
          ┌─────────┴─────────┐
          │                   │
      O QUE SABEMOS       O QUE NÃO SABEMOS
          │                   │
          └─────────┬─────────┘
                    ▼
             PRIMEIRO MODELO
                    │
                    ▼
            PRIMEIRA REPRODUÇÃO
                    │
                    ▼
               PRIMEIRA FALHA
                    │
                    ▼
             PRIMEIRO CARACOL
```

Eu deliberadamente **não começaria pela célula inteira, câncer, "descoberta de medicamentos" ou uma IA que tenta prever proteínas**. Isso seria grande demais.

Começaria por **um fenômeno quantitativo pequeno, público, reproduzível computacionalmente e suficientemente bem documentado para termos um chão firme**. A partir daí podemos descobrir se a arquitetura realmente funciona antes de colocar complexidade biológica em cima dela.
